# Windows 笔记本与 iPad 通过 SMB 局域网共享文件：免密码访问配置与排查

> 记录日期：2026-10-26  
> 使用场景：Windows 笔记本作为 SMB 文件服务器；iPad Pro（iPadOS“文件”App）作为客户端。  
> 目标：两台设备在同一可互访的局域网内，通过 iPad 查看、下载 Windows 指定共享文件夹中的文件。  
> 本次共享名：`Share_file`。  
> 结果：**iPad 已成功连接并访问所需共享文件夹，文件访问需求已实现。**

> **重要说明**：本记录基于实际对话与操作反馈。未取得 Windows 具体版本、最终各开关截图、`net share` 输出或权限列表，因此不将推测视为已经验证的根因。文中的 IP、路径和账户仅用于举例；**不包含真实 IP、密码或设备标识**。

## 1. 方案概要

- 传输协议：**SMB（Windows 文件共享）**。
- Windows：共享一个指定文件夹；开启可信网络下的网络发现和文件/打印机共享。
- iPad：无需安装第三方 App，使用系统“文件”App中的“连接服务器”。
- 连接方式：最初尝试“注册用户”失败，随后按需求改为**访客/客人访问**，最终实现访问。
- 文件访问范围：只需下载时推荐**只读**，不必向访客开放写入、修改、删除权限。

网络路径关系：

```text
Windows 笔记本（SMB 服务器）
  └─ Share_file（自定义共享）
         ↑  同一可互访局域网
iPad → 文件 App → 浏览 → ··· → 连接服务器 → smb://<电脑IPv4>
```

## 2. Windows 端配置步骤

### 2.1 准备文件夹

在电脑上创建一个专门用于传输的文件夹，实际位置可自定（例如 `D:\Share_file`）；本次对外发布的**共享名**为 `Share_file`。

避免将整个系统盘、`C:\Users` 或包含个人资料的目录作为匿名共享。

### 2.2 启用专用网络共享

在 Windows 11：

`设置 → 网络和 Internet → 高级网络设置 → 高级共享设置`

1. 将当前可信 Wi-Fi 网络设为**专用网络**。
2. 在“专用网络”下开启**网络发现**、**文件和打印机共享**。
3. 为实现免账户访问，先前采用过在“所有网络”下**关闭密码保护的共享**的方式。

**注意**：第 3 项会扩大局域网中的访问面。它不是所有 Windows 版本上匿名 SMB 必然可用的保证。只有在可信网络中且明确接受风险时使用。

### 2.3 发布 `Share_file`

对共享目录执行：

1. 右键目录 → **属性** → **共享** → **高级共享**。
2. 勾选**共享此文件夹**，共享名设为 `Share_file`。
3. 在**权限**中确保允许目标访客身份读取；常见的宽松设置是为 `Everyone` 授予**读取**。
4. 在**安全**选项卡核对 NTFS 权限；实际可访问权限同时取决于共享权限和 NTFS 权限。

> `Everyone` 并不在所有配置下自动等同于匿名来宾；是否能成功认证、读取还受系统来宾策略、账户及 Windows 版本影响。不要仅凭添加 `Everyone` 就认定“免密码配置完成”。

**安全建议**：只授予“读取/读取和执行/列出文件夹内容”，不要勾选更改或完全控制；对外仅共享非敏感的临时传输文件。

### 2.4 查看当前 IP 与共享列表

在 Windows 终端或 CMD 中：

```bat
ipconfig
net share
```

- `ipconfig`：查看当前 Wi-Fi 的 **IPv4 地址**，iPad 需要连接这台电脑的局域网 IP。
- `net share`：列出 Windows **实际发布的共享名和本地路径**，检查是否意外发布了其他目录。

本记录不保存真实 IP；以下使用示例 `192.168.1.105`。

## 3. iPad 端连接与下载

1. 确保 iPad 和笔记本处于**同一可互访局域网**；公共 Wi-Fi 的设备隔离可能阻止访问。
2. 打开 iPad **文件** App → **浏览** → 右上角 `···` → **连接服务器**。
3. 输入示例地址（替换为电脑的真实 IPv4）：

```text
smb://192.168.1.105
```

4. 如果 Windows 端允许访客访问，选择**客人（Guest）**，而非“注册用户”。
5. 连接后进入 `Share_file`。需要保存到 iPad 本地时，在共享位置选中文件并**拷贝**到“我的 iPad”中的目标目录。

也可以尝试直接输入 `smb://<电脑IPv4>/Share_file`，但这**不会**更改服务器实际开放的共享列表或权限。

## 4. 本次问题及实际排查经过

### 问题 A：使用“注册用户”时提示用户名/密码无效

**实际现象**：用户确认所输密码无误，但 iPad 提示：

> “你输入的服务器用户名或密码无效”

**讨论过的排查方向（未逐一验证）**：

- 用 `whoami` 确认本地用户名；在 iPad 尝试 `计算机名\本地用户名`。
- 区分 **Windows Hello PIN** 和真正的 **Windows 账户密码**。
- 如果使用 Microsoft 账户，可尝试 `MicrosoftAccount\邮箱` 加账户密码。
- 可为 SMB 单独创建带密码的标准本地账户，再按最小权限授予目录读取访问。

**此次处理**：用户明确表示不想用注册账户登录，因此改变方向，采用**免密码/访客访问**。未确认原认证失败的唯一根因，不应写成“密码确实错误”。

### 问题 B：连接成功，但 iPad 同时显示 `Share_file` 和 `Users`

**实际现象**：访客访问已能连接，iPad 显示两个共享入口：

- `Share_file`：自己配置的目标共享；
- `Users`：另外一个 Windows 发布的共享入口。

**含义**：SMB 服务器连接根目录展示的是**共享列表**，不只是某个共享里的子文件夹。仅凭 `Users` 名称不能确定其实际目录和可读权限。应在电脑上运行：

```bat
net share
```

确认 `Users` 的真实映射路径及是否仍有其他设备依赖它。

若确认为不需要的独立共享，且明确理解后果，可在**管理员 CMD**中取消该共享：

```bat
net share Users /delete
```

这会**取消网络共享**，不是删除硬盘里的 `Users` 文件夹；但会中断依赖该共享的连接。**本次没有确认执行过此删除命令**，因此仅作为可选处理，不视为已经实施的操作。不要删除 `C$`、`ADMIN$`、`IPC$` 等系统管理共享。

### 问题 C：关闭“公用文件夹共享”后 iPad 无法访问

**实际验证**：用户在 Windows 的高级共享设置中将**公用文件夹共享**关闭后，iPad 不能正常访问；此前的配置已经能够使用。用户随后反馈**目标访问需求已完成**。

**结论的边界**：

- 只能确认“**在这台电脑的当前设置中，关闭该选项后访问失效**”。
- 不能据此推断所有 Windows 设备都必须开启公用文件夹共享，才能访问自定义 `Share_file`。
- 也不能仅靠此现象认定 `Users` 的准确路径、匿名认证机制或各共享/NTFS 权限的原因。

**本次实用处理原则**：为了保留已能正常工作的共享访问，不再贸然修改会让连接失效的全局开关。如未来必须移除 `Users`，应先用 `net share` 确认共享，再逐项调整，而不是直接改变全局设置。

## 5. 出现连接问题时的建议排查顺序

| 现象 | 检查项 | 优先处理 |
| --- | --- | --- |
| 找不到服务器 / 连接超时 | 两设备网络、电脑 IPv4、电脑睡眠、路由器 AP 隔离、Windows 防火墙 | 先确保网络可达与文件共享规则放行 |
| 登录提示账户或密码无效 | 登录名格式、账户密码与 PIN、来宾访问策略 | 优先使用专用本地账户；不建议为排错关闭系统安全机制 |
| 可以进入服务器但不能打开文件 | 共享权限与 NTFS 权限 | 在目标目录设置最小必要读取权限 |
| 看到多余的 `Users` | Windows 实际发布的共享列表 | 用 `net share` 核对映射，不根据名称猜测 |
| 关闭“公用文件夹共享”后失联 | 全局设置与当前共享之间的交互 | 恢复已知可工作的配置，再分别核实共享与权限 |
| 更新 Windows 后 Guest 不再可用 | SMB 来宾认证/签名及系统版本策略可能变化 | 改用带密码的专用本地账户，而非强行降级协议 |

如装有 Clash/TUN 等网络代理软件，遇到局域网无法互通时，可以临时关闭用于排除路由问题，但不应直接认定它是本次登录故障原因。

## 6. 安全注意与恢复方式

**匿名 SMB 共享有风险**：同一局域网中有访问权限的其他设备可能读取公开内容；“文件夹是只读”不等于“文件本身已加密”。

建议：

- 仅在可信的家庭/私人局域网使用；不要在校园/酒店等不可信公共网络长期开放。
- **只共享一个用于传输的目录**，并限制为只读；不要存放身份证件、合同、账号信息等敏感材料。
- 传完文件后，可从“文件和打印机共享”设置中关闭共享功能，或在目标目录的“属性 → 共享”中取消共享；再次使用时按需恢复。
- 如匿名连接被新版 Windows 禁止，**优先创建带密码的独立标准账户并授予最小必要权限**。
- **不要**为此启用 SMB1、全面关闭防火墙、关闭 SMB 签名或随意放开整个 `C:\Users` 目录。
- 不要把本机实际 IP、账户信息或密码上传到公开仓库。
